PhoenixEvent design system

The brand book, tokens, components and icons of the PhoenixEvent design system. The live version, with each component as a working preview, is at https://claude.ai/artifact/LiN9xyts9t51qw9DCKk5mM.

Brand book

PhoenixEvent is the interface for people working an organization's event together, divided into stations. It serves PTAs, community committees, banks and businesses, so it reads plainly, works for a first-time volunteer, and keeps its meaning in every theme.

Content fundamentals

  • Labels and names are separate. "Event" and "Station" are default labels an administrator can replace with terms such as Function, Activity, Festival or Department. "Halloween Bash" and "Valentine Dance" are names. Write copy with the label as a variable in singular and plural form: "Join a {station}", "3 {stations} open".
  • Role titles are display text. Show the event's title for a role when it has one (Event Director, Event Chair, Event Executive, Event Manager) and the organization's title otherwise. Permissions keep their own stable names.
  • Sentence case everywhere: "Log in", "Forgot password?", "Join waiting list". Names keep their own capitals.
  • Buttons are a verb and its object: "Approve registration", "Appoint chair", "Remove from station". The toggle on a password reads "Show" or "Hide".
  • State what is true, in numbers: "9 of 10 places taken. Includes the chair." "3 on the waiting list."
  • Address the person as "you". The organization is named: "This link opens a site outside Lincoln Elementary PTA."
  • Errors say how to fix the value: "Enter 1 or more. Capacity includes the chair."
  • Words only. Emoji stay out of interface copy. Icons come from the Icons group.

Visual foundations

Themes. Three built-in themes share every token name. Set one with data-theme on the root or on any container.

Theme id Character
Sunbeam sunbeam Light. Warm paper surface, sun-gold brand. The default.
Moonshadow moonshadow Dark. Night-blue surface, pale moon brand.
Greystone greystone Neutral greys for people who see color differently. Roles differ by lightness, and icons and words carry the meaning.

Color.

  • Set the page on surface. Put cards, inputs, dialogs and the login panel on surface-raised. Use surface-sunken for meter tracks and inset boxes.
  • Set text in ink. Set hints and metadata in ink-muted.
  • Use brand as a fill only, with on-brand on top. It marks the one primary button in a view.
  • Set links and quiet buttons in brand-ink, always underlined.
  • Use border-strong for every edge a person needs to find: inputs, buttons, meter tracks, dialogs. Use border for decorative hairlines.
  • States use four roles, each a solid color on its own -surface tint: positive (open, approved, public), caution (pending, waiting list, nearly full), critical (full, error, destructive), neutral (cancelled, private, unlisted). positive is blue and critical is red, and they differ in lightness.
  • A state always appears as icon, word and color together. See StatusBadge.
  • Put scrim behind dialogs.

Contrast. ink, ink-muted and brand-ink hold 4.5:1 on all three surfaces in all three themes. Each state role holds 4.5:1 on its tint, on surface and on surface-raised. border-strong and focus hold 3:1 on all three surfaces. on-brand on brand and on-critical on critical hold 4.5:1. A new theme passes the same pairs.

Focus. Every interactive element shows a solid 3px focus outline with a 2px offset on keyboard focus.

Type. One family, sans, the system interface face, so pages load with no font download. mono shows addresses. Use display for the event name on a public page, heading-1 to heading-3 for titles, body for copy and inputs, small for hints and metadata, label for badges and scope lines. Body copy is 16px on a 24px line.

Spacing. A 4px base: space-1 to space-12. Use space-4 between form fields, space-6 inside cards and dialogs, space-8 between page sections.

Radius. radius-md for buttons and inputs, radius-lg for cards and dialogs, radius-pill for badges and meter tracks, radius-sm for inset boxes.

Shadow. shadow-raised lifts cards from surface. shadow-overlay lifts dialogs above scrim. Borders define edges, and shadows only add depth.

Layout. Controls are at least 44px tall. Forms are one column, with labels above inputs. Cards hold one subject each.

Motion. Still by default. State changes apply at once.

Iconography

Fourteen line icons on a 24px grid with a 2px stroke, in the Icons group. Inline them with stroke="currentColor" so each icon takes the color of its label.

  • Levels: organization, event, station. In ink, leading the scope line of announcements, navigation and page titles.
  • States: check-circle (approved, open), clock (pending approval), hourglass (waiting list), ban (full), x-circle (cancelled), alert (error, warning).
  • Visibility: globe (public), eye-off (unlisted), lock (private).
  • Links and files: external-link after any link that leaves the application, paperclip before an attachment.

Each icon sits beside its word. An icon standing alone takes an aria-label with the same word.

Logo

PhoenixEvent has no mark yet. Set the name in sans at weight 700, as one word with a capital P and a capital E.

Components

All components are CSS classes in components/bundle.css, prefixed pe-, and read only tokens. Button, TextField, PasswordField and LoginForm cover account screens. StatusBadge and CapacityMeter cover registration and station capacity. AnnouncementCard and ExternalLinkDialog cover communication. ThemeSampler shows one card in all three themes.

Components

Button

Starts a domain action such as Register, Approve, Appoint chair or Join waiting list. Classes: pe-btn plus one of pe-btn--primary, pe-btn--secondary, pe-btn--quiet, pe-btn--danger.

You provide: the label, the variant, and an optional leading icon (inline SVG with class pe-icon).

  • One pe-btn--primary per view, for the action the screen exists for.
  • Label the action with a verb and its object: "Remove from station", "Approve registration".
  • pe-btn--danger carries the alert icon and names what is removed. In Greystone its fill is close to the primary fill, so the words and the icon carry the meaning.
  • A button the person lacks permission or entitlement for is left out of the page. Use aria-disabled="true" for an action that exists and is waiting on something, such as a station at capacity, and say why beside it.
  • Minimum height is 44px in every variant.

TextField

A labelled single-line input with an optional hint and an error state. Classes: pe-field wrapping pe-field__label, pe-input, and pe-field__hint or pe-field__error.

You provide: the label text, the input's id, name and autocomplete, and hint or error copy.

  • The label sits above the input and is always visible. Placeholder text stays empty.
  • For an error, add pe-field--error to the wrapper, set aria-invalid="true", and point aria-describedby at the error line. The error line leads with the alert icon and says how to fix the value.
  • When an organization renames Event or Station, the label uses the configured term in its singular or plural form.

PasswordField

A password input with a Show/Hide button. The password is hidden by default. Classes: pe-field, pe-password wrapping a pe-input and a pe-btn pe-btn--secondary.

You provide: the label, the input's id and autocomplete value (current-password at login, new-password at reset), and the click handler that swaps the input type.

  • The button reads "Show" while hidden and "Hide" while visible. It is a real button type="button" with aria-controls pointing at the input and aria-pressed reflecting the state.
  • A role="status" line announces "Password is visible." or "Password is hidden." after each press.
  • The button keeps a fixed minimum width so the field holds its size when the word changes.

LoginForm

The login panel: a Username field, a Password field with Show/Hide, a "Forgot password?" link and one primary button. Class: pe-login on the form, composed from TextField, PasswordField and Button.

You provide: the organization name shown under the title, the form action, and the reset link target.

  • Exactly two fields: Username and Password. An email address is accepted in Username.
  • The organization name under the title shows which organization the session will belong to. How a person picks the organization is an open decision in the specification, so this panel displays the name and leaves the picker out.
  • A failed login shows one message above the fields that covers both fields together, so the response stays the same for every account.

StatusBadge

A pill that states one state with an icon, a word and a color role. Classes: pe-badge plus pe-badge--positive, pe-badge--caution, pe-badge--critical or pe-badge--neutral.

You provide: the state. The icon, word and role come from this table.

State Icon Role
Approved, Open check-circle positive
Public globe positive
Pending approval clock caution
Waiting list hourglass caution
Full ban critical
Cancelled x-circle neutral
Unlisted eye-off neutral
Private lock neutral
  • Every badge carries all three: icon, word, color. In Greystone the four roles are greys of different lightness, so the icon and the word identify the state.
  • The word is the state itself in sentence case, one or two words.
  • One badge per fact. A station that is full and private shows two badges.

CapacityMeter

Shows how many places of a station or event board are taken. Classes: pe-meter, with pe-meter--caution or pe-meter--critical, wrapping pe-meter__row, pe-meter__track and pe-meter__fill.

You provide: the station or board name, the count taken, the capacity, and the fill width as a percentage.

  • The count always appears in words: "9 of 10 places taken". The bar supports the sentence.
  • The chair counts toward capacity. Say "Includes the chair" beside the count.
  • Fill role: positive below 80 percent, pe-meter--caution from 80 percent, pe-meter--critical at capacity. These thresholds are a starting proposal.
  • At capacity, pair the meter with the Full StatusBadge and, where the waiting list is enabled, the number waiting.

AnnouncementCard

One announcement at organization, event or station level, with its links and attachments. Classes: pe-card pe-announcement, with pe-announcement__scope, __title, __body, __meta and a pe-attachments list.

You provide: the level and its name, the title, the body, the author's name and displayed role title, the date, and the attachment list (file name, type, size).

  • The scope line leads with the level icon (organization, event or station) and the configured label for that level.
  • The author line shows the role title as displayed for that event: the event override when one exists, the organization title otherwise.
  • A link that leaves the application carries the external-link icon and opens the ExternalLinkDialog.
  • Each attachment row shows the paperclip icon, the file name as a link, then type and size. Supported types: jpg, jpeg, png, md, html, pdf, doc, docx.
  • Images display inside the body. Uploaded and embedded video sit in a 16:9 frame between the body and the attachments.

ExternalLinkDialog

The warning shown when a person follows a link that leaves the application. It shows the destination and offers Continue and Cancel. Classes: pe-scrim behind a pe-dialog with pe-dialog__title, __body, __dest and __actions.

You provide: the full destination address and the organization name.

  • The destination shows in full in mono, wrapping at any character, so the whole address is readable.
  • Two actions, in this order: Cancel (secondary), then Continue (primary, with the external-link icon). Focus starts on Cancel. Escape cancels.
  • Use role="alertdialog" with aria-modal="true", labelled by the title and described by the body line.
  • Internal links go straight to their target, where the access check runs.

ThemeSampler

The same card in the three built-in themes, side by side: Sunbeam, Moonshadow and Greystone. Use it to judge a new theme against the built-in ones.

You provide: nothing. To apply a theme, set data-theme="sunbeam", data-theme="moonshadow" or data-theme="greystone" on the root element or on any container.

  • A theme added by a system, organization or event administrator supplies a value for every color token and passes the contrast pairs listed in the brand book before it ships.
  • A theme changes color and shadow tokens. Spacing, radius and type tokens stay shared.
